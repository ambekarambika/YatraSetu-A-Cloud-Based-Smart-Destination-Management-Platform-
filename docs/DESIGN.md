# YatraSetu — Design System

## 1. Design Direction

YatraSetu should feel:
- modern,
- classy,
- clean,
- realistic,
- tourism-focused,
- professional,
- slightly cinematic,
- culturally grounded.

It should not look like a generic SaaS, banking, CRM, or AI-generated admin template.

## 2. Public UI Status

### Landing Page — Frozen/Approved
The landing page uses:
- cinematic regional imagery,
- eight-state destination concept,
- translucent/glass search interface,
- destination pills,
- thumbnail strip,
- tourism ecosystem content,
- stakeholder coordination storytelling.

### Login — Frozen/Approved
- cinematic destination background,
- glassmorphic authentication card,
- role indicator,
- show/hide password,
- validation,
- YatraSetu branding.

### Registration — Frozen/Approved
- matching visual language,
- Tourist / Destination Manager / Stakeholder role selection,
- password strength meter,
- validation.

Do not modify these pages casually.

## 3. Shared Application Design

Current shared UI:
- compact dark navy sidebar,
- minimal topbar,
- user profile badge,
- search/select controls,
- white content cards,
- light application background,
- dark readable typography,
- data tables,
- status badges,
- restrained glassmorphic modals.

Primary application surfaces should remain neutral so state accents do not overwhelm usability.

## 5. Manager Workspace Design

The Manager workspace is the central management UI and contains ten pages:

1. Overview
2. Destinations
3. Attractions
4. Events
5. Stakeholders
6. Visitor Statistics
7. Feedback
8. Analytics
9. Reports
10. Decision Support

The visual reset aimed to eliminate:
- excessive cards,
- nested cards,
- visual noise,
- generic SaaS layouts,
- unnecessary diagrams,
- sci-fi aesthetics.

## 6. Manager Overview

The current intended overview contains:
- state hero/context,
- four key metrics,
- activity timeline,
- stakeholder feed,
- upcoming events,
- feedback preview,
- sustainability messaging.

The destination context selector is an explicit options-wise dropdown.

## 7. Manager Detailed Pages

### Destinations
Search/filter interface, destination table, add-destination modal.

### Attractions
Attraction directory, crowd status, operating hours, add-attraction modal.

### Events
Festival/event schedule, status filters, add-event modal.

### Stakeholders
Tourism service-provider directory with verified indicators.

### Visitor Statistics
Visitor volume metrics, day-of-week strain, origin-state breakdown.

### Feedback
Ratings, sentiment filters, feedback moderation table.

### Analytics
Destination capacity, local economy/spend indicators, eco-preservation metrics.

### Reports
Report parameter configuration, report-preview simulation, PDF/CSV export triggers.

### Decision Support
Data signal → observation → management consideration structure.

## 8. Design Integrity Rules

- Do not add decorative UI without purpose.
- Prefer real tourism imagery over abstract graphics.
- Keep information density controlled.
- Use consistent spacing and typography.
- Keep buttons and controls predictable.
- Avoid excessive glass effects.
- Preserve accessibility through readable contrast.
- Responsive behavior should be considered for every new page.
- Do not introduce a new visual language for every role.

## 9. Future Role Workspaces

Stakeholder, Tourist, and Administrator workspaces should reuse the shared design foundation but have role-specific content.

Do not copy Manager metrics/content into other roles.
